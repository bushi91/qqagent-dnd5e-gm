# D&D 5e 跑团主持（QQ Agent 技能 · 第一版）

让群里的机器人当 D&D 5e 的 DM：建角色卡、掷骰、做检定、跑战斗回合、写场景摘要。
**所有随机数、HP、先攻都由代码计算，模型只负责叙述** —— 这是本技能存在的唯一理由。

---

## 为什么是「技能」而不是「插件」

按项目文档 `doc/extend_development/` 第 0 节的判定：需要模型判断"什么时候用、怎么用、要不要加值"的能力放 **skills/**（会进提示词、模型主动调工具）；纯事件驱动、不需要模型思考的放 **plugins/**。

跑团需要模型在"玩家说我要推门"时决定该掷什么骰、给不给优势——所以是技能。
（如果你以后想要"每天自动播报一次战报"这种不经过模型判断的定时任务，那才是插件。）

## 装在哪

```
<QQ Agent 项目根>/
└── skills/
    └── dnd5e-gm/          ← 整个目录复制过去即可
        ├── skill.json
        ├── index.js
        └── lib/
            ├── dice.js    ← 骰子表达式解析（NdM±K、优势/劣势）
            └── store.js   ← 按会话存取跑团存档（data/dnd/<chatKey>.json）
```

装好后不用重启（项目开着热重载），QQ Agent 的 **技能** 页会出现「D&D 5e 跑团主持」，默认启用。

## 怎么玩

群里任何一句话都能触发（模型自己判断要不要进跑团模式）：

- 「开个团，3 级，给我来个盐沼悬疑」→ 开团
- 「我建个角色，老陈，战士 3 级，16 力量」→ 建卡
- 「我要踹开这扇门」→ 力量检定，骰子公开发群
- 「它扑过来了」→ 开战（先攻自动掷），谁的血谁扣
- 「这幕结束了，记一下」→ 写 200 字摘要，长团不爆上下文

玩家也可以直接问：「看团况」「我们谁先攻」「刚才那个骰多少」。

## 它替模型管住了什么

| 事情 | 谁做 |
| --- | --- |
| 掷骰、优势/劣势、暗骰 | `dnd_roll` / `dnd_check`（公开骰自动发群） |
| 命中扣血、倒地判定、回血 | `dnd_damage` / `dnd_heal` |
| 先攻排序、轮次推进、跳过尸体 | `dnd_combat` |
| 角色卡、长休 | `dnd_sheet` |
| 场景与剧情摘要 | `dnd_scene`（进入后续上下文，替代整段对话） |
| **叙述、NPC 台词、剧情走向** | 模型 |

提示词里写死了「骰子必须由工具算、不许自己编数字」，以及每幕 200 字摘要的纪律。

## 自检

不装进 QQ Agent 也能验证：

```powershell
node selftest.mjs
```

覆盖骰子表达式、工具注册、开团→建卡→检定→受伤→治疗→开战→轮转→击倒→摘要→日志 全流程，以及"没开团的会话不注入提示词"。

## 配置项（QQ Agent 技能页可调）

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `enabled` | 启用跑团技能 | true |
| `maxParty` | 队伍人数上限 | 6 |
| `publicRolls` | 骰子是否公开到群里 | true |
| `maxLog` | 判定日志保留条数 | 200 |

## 已知边界（第一版故意没做的）

- 没有内置 SRD 怪物/法术数据表：怪物由 DM 现编，用 `dnd_combat start` 传入 `名字:先攻:HP[:AC]`。
- 经验值只给叙述建议，不自动结算升级。
- 地图是简化版（12×9 格 + 几个柱子），做距离/射程/移动力判定，不做掩体、视线、借机攻击位移等细节。
- 存档按会话隔离：换群就是新团。

## 排错

| 现象 | 原因 |
| --- | --- |
| 技能页显示加载失败 | `skill.json` 有 BOM 或 JSON 语法错；或 `index.js` 有顶层语法错（`node --check index.js`） |
| 技能加载了但机器人不掷骰 | `config.skills["dnd5e-gm"].enabled` 为 false，或提示词被别的技能覆盖 |
| 骰子结果没发到群里 | 机器人没有主动消息权限；工具仍返回结果，模型会用 `send_message` 播报 |
| 团不见了 | `data/dnd/<chatKey>.json` 被清；或换了群（存档按会话） |

## v1.1 更新（第二版，2026-10-29）

第一版实测暴露两个问题：**玩家挨打后血量不扣**、**剧情卡着不推进**。这一版把它们和四条新需求一起解决。

### 新增工具（共 17 个）

| 工具 | 作用 |
| --- | --- |
| `dnd_ready` | 玩家逐项确认角色卡，全员确认才允许开场 |
| `dnd_start` | 开场：写入这一幕目标，并给出地点/事态/可选方向 |
| `dnd_objective` | 设定或查看当前目标（换场景、新幕必须更新） |
| `dnd_map` | 显示战场地形、所有人位置、与敌人的距离 |
| `dnd_move` | 移动（每回合 6 格，撞柱子会被拒） |
| `dnd_attack` | 一次攻击的完整结算：对 AC、掷伤害、扣血、判射程、扣动作，并自动播报 |
| `dnd_action` | 攻击/施法之外的举动，判定消耗哪类动作并扣除，返回剩余 |

### 修了什么

1. **血量不扣**：根因是 `dnd_damage` 只认已登记目标，敌人名字没登记时直接报「找不到目标」，模型就改用叙述带过。现在 `dnd_damage`/`dnd_attack` 遇到未登记敌人会**自动建档**；攻击走 `dnd_attack` 一条龙，不再需要模型自己拼三项工具。
2. **卡关**：提示词新增硬规则「同一障碍最多两次检定，第二次失败必须换路（线索/代价/时间压力/新敌人），失败也必须产生变化与情报」；同时加「同一障碍反复回来」的禁止项。

### 新增玩法

- **开局流程**：`dnd_new` → 每人 `dnd_sheet` → 玩家说「就这样」触发 `dnd_ready` → 全员确认 → `dnd_start` 定目标 → 第一个场景。没确认完，开场会被工具拒绝。
- **目标**：每幕都有 `objective`，会写进状态摘要与提示词；换场景/每 3 轮/玩家迷茫时机器人要重申一次。
- **地形**：12×9 格（每格 5 尺，斜走算 1 格），开战时按先攻摆位，柱子在中间区域随机 2~4 个。近战 1 格、远程 12 格，够不着时工具直接拒绝并给出距离。
- **行动经济**：每回合 动作 / 附赠动作 / 反应 / 移动 6 格。攻击施法之外的举动走 `dnd_action`，回复里必须说明消耗了什么、还剩什么；用完了只能等下一轮。

### 自检

`node selftest.mjs` 仍是 30 项全过；新工具的初始化（`ensureGrid`/`placeTokens`/`turnOf`）在开战与攻击路径上被覆盖。
